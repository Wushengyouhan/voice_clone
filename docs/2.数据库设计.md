# 语音合成项目数据库设计（精简版 V1）

## 1. 设计原则

- 先按 MVP 落地，优先保证链路可跑通
- `Voice` 按你要求精简为最小字段集
- `Synthesis` 仅保留同步合成所需核心信息

## 2. 表结构总览

V1 使用两张表：

1. `Voice`：音色基础信息
2. `Synthesis`：合成任务记录

关系：

- 一个 `Voice` 可以有多个 `Synthesis`（1:N）

## 3. Voice（音色表）

按当前需求，字段只保留以下 5 个：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | String (PK) | 本地主键，`cuid()` |
| `name` | String | 音色名称 |
| `sampleUrl` | String | 样本音频 URL（OSS） |
| `voiceId` | String + unique | 阿里云返回的音色 ID |
| `createdAt` | DateTime | 创建时间 |

## 4. Synthesis（合成任务表）

用途：记录每一次“某音色 + 某段文本”的语音合成请求和结果。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | String (PK) | 本地任务主键，`cuid()` |
| `voiceId` | String (FK) | 关联 `Voice.id` |
| `text` | Text | 待合成文本 |
| `outputUrl` | String? | 合成结果音频 URL（OSS） |
| `durationMs` | Int? | 音频时长（毫秒，可选） |
| `createdAt` | DateTime | 创建时间 |
| `updatedAt` | DateTime | 更新时间 |

索引设计：

- `@@index([voiceId, createdAt])`
  - 用于“按音色查看历史合成记录”场景

## 5. 关键约束与规范

- `Voice.voiceId` 唯一，避免重复绑定同一个云端音色
- 文本字段使用 `Text`，避免长文本截断

## 6. 建表示例（Prisma）

当前 Prisma Schema 已落地上述结构，见 `prisma/schema.prisma`。

迁移命令（本地开发）：

```bash
npm run prisma:generate
npm run prisma:migrate -- --name init_voice_tables
```

## 7. 下一阶段建议（V1.1）

当你开始做登录和多租户时，建议扩展：

- `User` 表（账号体系）
- `Voice.userId`、`Synthesis.userId`（数据隔离）
- `Voice.status`（训练状态）
- `Voice.updatedAt`（更新时间）
- `Synthesis.status`（如果改为异步合成）
- `Synthesis.providerTask`（异步任务跟踪）
- `errorMessage` 字段（保存失败原因）
- `deletedAt` 软删除
- `requestId` 幂等键（防重复提交）
